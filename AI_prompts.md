## Problem 8: Customer memory

**Prompt:**
When a shopper is logged in, save their chat history in the database in an appropriate table and reload it when they return. The agent should know who is chatting (name, email) — put that in agent deps (or an equivalent clear pattern) and/or tools the agent can call. Also pass enough page context that if someone is on a product page and asks "do you have this in pink?", the agent knows which item they mean (hint: you can put code into the agent context). Guests can still chat, but history only needs to persist for logged-in users. Document in `output/harness.md`: how user chat history is stored, what customer fields the agent sees, and how page context is passed.

**Follow-up:** None needed from you, but two real bugs surfaced and got fixed while verifying this end to end. First: the very first page-context test I ran ("do you have this in a large?" on a product's own page, no product named) *didn't* use the page context — it fell back to asking "which item did you mean?" instead of resolving to the current page's product. Traced it to the keyword search itself: "large" and "small" are ordinary words that show up constantly in this catalogue's own description text ("large white YALE lettering"), so a pure size question was spuriously finding real catalogue matches, which meant the page-context fallback (which only kicks in when search finds *nothing*) never got the chance to run. Fixed by excluding garment-size words from search tokens — a size alone should never drive catalogue search, it's a follow-up on whatever's already in view. Second: while testing that the agent shouldn't overstep its actual capabilities, I noticed a reply casually offer to "help you get one added to your cart" — this site has no cart or checkout at all, so I added an explicit rule to `prompts/prompt.md` telling the model not to offer or imply cart/checkout/hold features that don't exist. Re-verified both after fixing: the size question now correctly resolves via page context (checked against real inventory numbers), and the cart offer no longer appears.
